## Topics

- What offensive security means in a classroom (authorised, in-scope lab only)
- Difference between attacking a training target and attacking a system you do not own
- A first look at how a simple web target can be examined in a guided environment

## Tools used

Platform lab environment and the room’s walkthrough. No tools aimed at hosts outside TryHackMe.

## Concepts learned

Offensive work is scoped: you only test what you are allowed to test. A walkthrough room teaches the *shape* of an engagement, not independent exploitation skill.

## Practical skills

Follow a guided intro lab to completion. Record that it is introductory. Map the idea of “authorised target” to this repository’s localhost-only rule.

## Developer perspective

The engineering equivalent is not “hack a site”. It is: own the application, reproduce a missing control, fix it, and test it. That loop already exists for [WEB-001](../../reports/WEB-001-broken-object-level-authorization.md) and [WEB-002](../../reports/WEB-002-authentication-security.md). This room does not replace those labs.

## Security implications

Without scope, “offensive” practice becomes an attack on someone else’s system. [lab-rules.md](../../docs/lab-rules.md) forbids that.
